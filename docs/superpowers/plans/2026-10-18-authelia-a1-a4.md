# Authelia A1–A4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish a configuration-safe Authelia forward-auth boundary and a single client API wrapper, without changing the existing demo experience.

**Architecture:** Add a small, pure auth layer for environment parsing and forwarded-identity validation. Next.js Proxy applies the request boundary (CSRF origin guard, proxy secret, and machine-route header stripping); route handlers expose only demo-only login and a smoke-test identity endpoint. Client UI calls move through one wrapper that identifies expiry consistently.

**Tech Stack:** Next.js 16 Proxy and route handlers, TypeScript, Vitest, ESLint.

**Spec:** `docs/adr/0002-auth-and-sessions.md` (units A1–A4)

## Global Constraints

- Support only `CLIENT_BILLING_AUTH_MODE=demo|authelia`; refuse `CLIENT_BILLING_ENV=production` with demo mode.
- Authelia proxy secret has a minimum length of 32 bytes and is required only in Authelia mode.
- Demo identity routes return 404 outside non-production demo mode.
- All client requests use the API wrapper; it sends `X-Requested-With: XMLHttpRequest` and `redirect: 'manual'`.
- Do not bind verification to port 3000; use `.claude/skills/verify/` after implementation.

## Review Focus

- Empty or malformed forwarded usernames must be rejected before a route sees them (Task 3).
- A same-length-but-wrong proxy secret must fail with the same 401 result as a missing secret (Task 3).
- Cookie-bearing mutation requests without a same-origin `Origin` must be denied, while bearer machine requests remain usable (Task 2).
- An opaque redirect must reload exactly once, and successful requests must never reload (Task 4).
- No direct client `fetch` remains in `src/app` or `src/components` after migration (Task 4).
